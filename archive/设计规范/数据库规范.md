- PostgreSQL 设计规范。
# 表命名
- 表名称使用一个或多个英语单词命名，每个单词全部小写，单词间使用下划线连接。
- 单词使用单数形式，不使用复数形式，不使用时态、语态、分词。
- 单词选用尽量避免保留字。
- 表明名原则上不得使用缩写。
# 字段命名
- 字段名称使用一个或多个英语单词命名，每个单词全部小写，单词间使用下划线连接。
- 字段名称原则上不得使用缩写，例如seq，除非是广泛使用，约定俗成的，例如id、html。
- 单词使用单数形式，不使用复数形式，不使用时态、语态、分词。
- 单词选用尽量避免保留字。
- 表主键字段通常使用id作为其命名。
- 字段如果与其他表构成外键关系，不需要在名称中加id字样。
- 多个并列关系的字段，尽量选择等长的单词，如选择start_time、final_time，而不是end_time。
# 字段类型
- 存储字符串的字段，通常使用 varchar 类型，长度与预期长度相当，超长的字符串字段，通常使用 text 类型。
- 存储UUID的字段，通常使用 varchar(40) 类型。
- 存储整数的字段，通常使用 int 类型。
- 存储浮点数的字段，通常使用 float 类型。
- 存储日期时间字段，通常使用 timestamp 类型。
- 存储布尔值的字段，通常使用 boolean 类型。
# 字段其他
- 不应存在空值的字段，需要设置不允许为空。
- 字段一般不设置默认值。
# 注释
- 所有表、所有字段必须有注释。
- 注释使用中文，以4-6个汉字为佳，末尾不加标点。
- 对于需要特别说明格式的字段，注释后以中文括号包含格式说明，例如 小说编码（UUID）。
- 对于表示枚举值的字段，注释后以中文括号包含枚举的值和含义，例如 人物性别（01：男，02：女）。
- 对于表示枚举值的字段，枚举的值一般采用两位或多位等长的数字字母序列，例如 01、02、03 等。
# 约束
- 所有表都要有主键，以单一字段主键为佳。
- 在逻辑关系上需要有外键的字段，就建立外键。
- 在逻辑关系上需要有唯一约束的字段，就建立唯一约束。
- 外键约束一般不使用级联更新、级联删除。

# 实施约定
## 命名
- 表示序号的字段统一使用 serial，不使用 seq、sort_number、sequence。
- 表示起止的成对字段统一使用 start、final，不使用 start_position、end_position。
- 成对或并列的字段，单词长度保持一致，例如 start / final、launch_time / finish_time、total_count / embed_count。
- 布尔字段使用名词本身，不加 has、is 等前缀，例如 vector，不使用 has_vector。
- 统计类字段省略所属对象前缀，使用 total_count、embed_count 等短词。
- 文件类型字段存储扩展名（txt、pdf、docx），不存储数字枚举码。

## 约束
- 建表语句中不指定约束名称，使用 PostgreSQL 默认命名：主键为 表名_pkey，唯一约束为 表名_字段名_key，外键为 表名_字段名_fkey。
- 不建立 CHECK 约束。
- 除主键与唯一约束自动生成的索引外，不额外建立索引。

## 类型与可空
- 状态码字段使用 varchar(2)，取值为两位数字码。
- 文件摘要字段使用 varchar(80)。
- 文件类型字段使用 varchar(10)，名称与标题字段使用 varchar(200)。
- 除表示尚未发生的时间字段（如 finish_time）外，所有字段禁止为空。
- 字段一般按主键、外键、业务字段、统计字段、时间字段的顺序排列。

## 注释
- 表注释使用四个汉字概括，例如 原始文件、小说信息、章节信息、分片信息、处理进度。
- 布尔字段注释直接描述状态，例如 已有向量，不附加 true/false 说明。
- UUID 字段注释统一写作“XX编码（UUID）”。
