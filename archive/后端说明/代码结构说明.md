# 代码结构说明

本文说明 Go 后端的分层结构，以及每一层的职责与依赖关系。后端位于 service 目录，采用 Gin 框架，按"入口 → 接口 → 业务 → 存储"单向依赖组织，任务处理通过独立的后台调度层运行。

## 1. 分层总览

| 层级 | 目录 | 职责 |
| :--- | :--- | :--- |
| 入口层 | service/main.go | 按顺序初始化各层、注册路由、启动 HTTP 服务 |
| 配置层 | internal/config | 读取配置与提示词，编译期嵌入二进制 |
| 公共层 | internal/common | 与业务无关的通用能力：工具函数、枚举、中文分词与 BM25 计算 |
| 网络层 | internal/server | 中间件、统一响应体、流式响应、令牌签发与校验 |
| 接口层 | internal/handler | 路由注册、请求参数解析、调用业务层、返回响应 |
| 业务层 | internal/service | 组织业务逻辑，协调存储层与任务层完成一个完整场景 |
| 任务层 | internal/pipeline | 后台调度处理任务：解析、切分、向量化入库 |
| 存储层 | internal/storage | 对外部中间件的统一封装：PostgreSQL、Qdrant、MinIO、模型服务 |

依赖方向是单向的：main → handler → service → storage，pipeline 由 main 启动、被 service 触发，server 与 common 被各层共用。

## 2. 各层说明

### 2.1 入口层（main.go）

只做编排，不含业务逻辑。启动顺序如下：

1. 设置日志级别；
2. 初始化分词组件（common.Initialize，词典加载失败即退出）；
3. 初始化存储层（storage.Initialize，同时确认向量集合存在）；
4. 初始化业务层（service.Initialize，只创建对象，不连接外部资源）；
5. 初始化接口层（handler.Initialize）；
6. 启动后台任务调度（pipeline.Initialize）；
7. 设置 Gin 运行模式、挂跨域中间件、注册路由、监听端口。

storage 与 pipeline 通过 defer 注册回收，进程退出时先停调度再断连接。

### 2.2 配置层（internal/config）

- config.yaml 通过 //go:embed 在编译期嵌入，运行时不依赖外部文件；改配置必须重新编译；
- 配置分四段：station（端口、运行模式、并发数、摘要开关）、postgres、qdrant、minio、models（大模型、小模型、向量模型各自的地址、密钥、模型名、超时）；
- 提示词同样嵌入：abstract.txt（分片摘要）、compress.txt（历史对话压缩）等，以全局字符串变量暴露给业务层使用。

### 2.3 公共层（internal/common）

不依赖数据库、不依赖 Gin，可被任意层调用：

- util.go：文本处理辅助函数——泛型三目 If、Trim（空串转 nil）、Split / Join、按字符截断 Truncate；
- enum.go：全局常量——支持的文件类型、任务状态码（01~08）、用户权限标识；
- bm25.go：中文分词（gse）与 BM25 稀疏向量计算 GetMatching，纯函数，同一段文本永远得到相同结果，不依赖数据库。分词器需先经 Initialize 显式加载。

### 2.4 网络层（internal/server）

处理"与 HTTP 协议相关、与具体业务无关"的部分：

- middle.go：跨域中间件 CrossDomain；登录校验 TestLogin、权限校验 TestPermit（从 Authorization: Bearer 解析令牌，无权限直接返回 403）；
- identity.go：JWT 的签发与解析，令牌中携带用户编码与权限集合；
- result.go：统一响应体 Result{success, failure, message, content}，以及成功码和各类失败码常量；
- answer.go：AnswerWriter，把响应切换为 SSE（text/event-stream），逐段推送 type + content，用于问答过程的流式输出。

### 2.5 接口层（internal/handler）

- handler.go：参数解析基类，提供 getString / getInt / getInt32 / getInt64，统一做去空格与空串转 nil；
- account.go / prepare.go / discuss.go：各自实现 register，在 Register 中集中挂到 Gin 引擎；
- 该层只负责"取参数、调方法、包响应"，不写业务判断，也不直接访问存储。

### 2.6 业务层（internal/service）

一个文件对应一个业务场景，通过包级变量对外暴露单例：

- accountService：登录、用户管理、词元消耗统计；
- prepareService：原始文件上传、文本解析、章节与分片任务创建、小说与任务列表查询；
- discussService：会话创建与查询、会话的小说范围筛选、消息历史；
- composeService：问答编排——压缩历史对话、改写检索问题、混合召回分片、组装提示词、调用大模型并流式回推。

业务层是唯一编排"存储层 + 任务层"的地方，例如创建任务后由任务层按状态推进。

### 2.7 任务层（internal/pipeline）

独立于 HTTP 请求的后台处理链，按任务状态顺序推进：

- init.go：用 context + sync.WaitGroup 管理调度协程的启停；
- schedule.go：定时扫描待处理任务，按状态分发到下一环节，并在失败时记录重试；
- normalize.go：从对象存储读取原始文件，按类型（txt / md）解码、清洗编码（含 GBK 转 UTF-8），统一另存为 Markdown；
- organize.go：按章节切分，再按长度切分片（前缀 / 主体 / 后缀三段，相邻分片有重叠），写入章节表与分片表；
- vectorize.go：分批取分片，计算原文向量、可选摘要向量与 BM25 稀疏向量，写入向量数据库，并回写进度。

每个任务在库中都有状态字段，任务层只做"当前状态的下一步"，因此进程重启后能从未完成处继续。

### 2.8 存储层（internal/storage）

把外部中间件封装成包级单例，向上提供语义化方法，屏蔽 SDK 细节：

- postgre.go（RDB）：连接池与查询封装（单值、多行、执行）；
- qdrant.go（VDB）：集合创建（命名稠密向量 + 稀疏向量）、点的写入与删除、混合检索；
- minio.go（OSS）：对象上传、下载、删除；
- model.go（LLM / SLM / VEM）：OpenAI 兼容接口，分别对应大模型、小模型、向量模型，统一封装对话、直答与向量计算；
- init.go：按配置建立全部连接，任一失败即终止启动；Dispose 负责释放。
